# TASK_WRITING.md

## Task 문서 위치

`Tasks/<kebab-case-이름>.md` 형식으로 저장합니다.  
예: `Tasks/ai-retouch-impl.md`

## 기본 원칙

- task 문서는 현재 단계에서 필요한 결과와 검증 기준을 고정하는 문서입니다.
- task 문서에는 기본적으로 What, 즉 무엇이 필요한지를 적습니다.
- 구현 전 task 문서에는 How, 즉 클래스 구조, 호출 순서, 내부 구현 방식, Inspector 연결 방법을 추측해서 적지 않습니다.
- 구현 후에는 실제 추가된 코드를 기준으로 task 문서를 갱신합니다.
- 사용자 요청과 현재 task 범위를 벗어나는 항목은 task 문서에 추가하지 않습니다.
- 다음 task에서 구현할 흐름이나 아직 연결되지 않은 자동 동작을 현재 task의 검증 항목처럼 적지 않습니다.
- 새 task 문서를 생성하면 `docs/PLANS.md` 작업리스트의 해당 단계 `Task 문서` 칸도 생성한 task 문서 링크로 갱신합니다.

## 작성 규칙

- `Tasks/_template.md`를 복사해서 시작합니다.
- 목표는 한 문장으로 씁니다.
- 완료 조건은 체크 가능한 항목으로 나열합니다.
- 구현 중 범위가 변경되면 task 문서를 먼저 갱신하고 사용자 확인 후 진행합니다.

## 구현 후 갱신 규칙

- 완료 조건 체크리스트를 채웁니다.
- 상태를 `done`으로 변경합니다.
- 실제 구현과 달라진 결정사항이 있으면 `## 결정 사항` 섹션에 기록합니다.
- `docs/PLANS.md` 상태도 함께 갱신합니다.

## 금지

- task 문서에 반복 규칙을 복사하지 않습니다. 규칙은 `docs/` 문서를 참조합니다.
- 완료되지 않은 task에 다음 task 내용을 미리 적지 않습니다.
